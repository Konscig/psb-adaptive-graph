# API Inventory: анализ наполненности НБС — ПСБ × ИТМО

> **Версия:** 0.1 — рабочий контракт для планирования  
> **Дата:** 2026-11-18  
> **Основано на:** `artifacts/usm.md` (итерация 1), `artifacts/er-diagram.md` (v0.3), `artifacts/c4-architecture.md` (v0.6), `artifacts/nfr.md`, `artifacts/brief.md`.  
> **Статус:** предложения по маршрутам и контрактам; не OpenAPI и не утверждённая спецификация.

## Обзор

**Всего endpoints:** 24.  
**API Style:** REST, `/api/v1/`.  
**Форматы:** JSON по умолчанию; `multipart/form-data` для предварительного разбора файла; PDF/PPTX возвращаются как бинарные файлы с `Content-Disposition: attachment`.  
**Базовый URL — гипотеза:** `http://127.0.0.1:<API_PORT>/api/v1`; порт в C4 не задан.  
**Авторизация:** отдельного входа в локальном MVP нет — подтверждённое решение. Auth endpoints не предлагаются. Способ демонстрации различий между администратором и пользователем анализа не выбран; строки с операциями записи ниже указывают логическую роль, но не подразумевают готовую защиту API. Для будущего доступа внутри Банка аутентификацию и права нужно отдельно согласовать с ИБ.

Предполагается синхронная обработка для локальной демонстрации. Если импорт, расчёт рекомендаций или экспорт не укладываются в запрос-ответ, потребуется асинхронный job API и Sequence diagram. Размеры файлов, пределы выдачи и временные ограничения пока не определены.

### Общие правила

- Идентификаторы ресурсов в URL — UUID из ER. Идентификаторы источника, ИНН и КПП передаются и хранятся как строки.
- Записи `Client ID` сопоставляются между срезами по основному ключу `source_client_id`. ИНН/КПП используются только для проверки и не переопределяют клиента.
- Фильтры и сортировка применяются на backend; API возвращает выбранный срез и нужные агрегаты, а не весь портфель.
- В списках рекомендуется единый формат `?page=1&limit=50` и ответ `pagination { page, limit, total }`. Значения по умолчанию/максимум нужно сверить с размером синтетического набора.
- Для snapshot-профиля и продуктового состояния предполагается работа с выбранным срезом. Правило редактирования уже использованного/исторического среза не определено; до решения не перезаписывать исторические значения молча.
- Удаление клиентов, срезов, рекомендаций и продуктов не включено: соответствующей истории нет, политика хранения не согласована.

## 2. Импорт и срезы

| Method | Path | Auth / роль | Description | User Story |
|---|---|---|---|---|
| POST | `/imports/preview` | Без входа; администратор по сценарию | Разбирает XLSX/CSV, показывает распознанные поля, предложенное сопоставление и ошибки строк; нормализованные данные не фиксирует. | US-001, SS-001 |
| POST | `/snapshots` | Без входа; администратор по сценарию | Подтверждает preview и создаёт срез с датой и сопоставлением полей. | US-001, SS-001 |
| GET | `/snapshots` | Без входа | Список срезов для выбора периода. | US-002, US-009 |
| GET | `/snapshots/{snapshot_id}` | Без входа | Метаданные конкретного среза, дата и итог импорта. | US-002, US-009 |

### `POST /imports/preview`

**Request:** `multipart/form-data`: `file` (XLSX или CSV UTF-8; запятая/точка с запятой для CSV). Старый XLS не поддерживается.  
Файл может включать клиентские и продуктовые поля, сведения о конкурентах/условиях и заметки сотрудника согласно US-001. Подготовленный открытый контекст можно принять тем же импортом после выбора его структуры и сопоставления; отдельный коннектор к внешнему источнику не предполагается.  
**Предлагаемый `200` response:** `preview_id`, найденные колонки, предполагаемое сопоставление, числа корректных/сомнительных строк и `issues[]` с номером строки, полем, кодом и пояснением. Preview не записывает нормализованные сущности в постоянную БД; временное хранение результата до commit и срок его жизни нужно определить.  
**Ошибки:** `400` нечитаемый файл/параметры; `413` файл больше установленного предела (предел пока не задан); `415` неподдерживаемый формат; `422` файл не соответствует ожидаемой структуре.

### `POST /snapshots`

**Request JSON:** `preview_id`, `snapshot_date`, подтверждённый `column_mapping`; при необходимости `row_decisions[]` для включения/исключения неоднозначных строк — предложение для обсуждения.  
**Предлагаемый `201` response:** `snapshot_id`, `snapshot_date`, `import_status`, счётчики принятых/исключённых строк и список оставшихся проблем.  
**Ошибки:** `404` preview не найден; `409` preview уже использован/просрочен или Client ID повторяется внутри загружаемого набора; `422` структура или идентификаторы не проходят проверку.

**Открытый контракт:** нужно выбрать, разрешает ли MVP частичный импорт. Предварительный вариант — не включать сомнительные строки в анализ и явно вернуть их ошибки; фиксировать строку `snapshot` с `partial` только после подтверждения этого поведения. Срок жизни preview и хранение исходного файла не заданы. Проверку ИНН/КПП нельзя реализовывать до согласования формата: USM указывает 12 цифр для ИНН, а схема содержит клиентов-юрлиц, Client ID выбран основным ключом, КПП в XLSX нет.

## 4. Покрытие и карточка клиента

| Method | Path | Auth / роль | Description | User Story |
|---|---|---|---|---|
| GET | `/coverage/graph?snapshot_id={id}&product_id={id}` | Без входа | Фильтрованный подграф покрытия и агрегаты по выбранному НБС; дополнительные фильтры — регион, сегмент, активность и другие согласованные поля. | US-002, US-003, US-005 |
| GET | `/clients/{client_id}/profiles/{snapshot_id}` | Без входа | Профиль клиента на выбранную дату, его продуктовые состояния и связанный контекст/сведения. | US-004, US-006 |
| PATCH | `/client-profiles/{profile_id}` | Без входа; предполагаемое действие администратора | Правка атрибутов клиента в конкретном срезе. | US-012 |
| PUT | `/client-profiles/{profile_id}/products/{product_id}` | Без входа; предполагаемое действие администратора | Создать/заменить состояние продукта клиента в срезе: наличие и даты подключения/отключения. | US-012 |
| PATCH | `/evidence-items/{evidence_id}` | Без входа; предполагаемое действие администратора | Исправить импортированную заметку или контекстное сведение. | US-012 |

`GET /coverage/graph` возвращает узлы, связи, легенду/типы и агрегаты только для выбранного среза. `GET` профиля может включать сведения из открытых источников только при сохранённом происхождении; несопоставленные и агрегатные записи не привязываются автоматически к синтетическому клиенту.

Редактирование должно сохранить смысл сравнения периодов. Открыто, редактируются ли только ещё не использованный срез, текущий срез с фиксацией версии или администратор создаёт новый срез; до решения PATCH/PUT — предложенные маршруты, не окончательный контракт. Политика удаления не задана.

## 5. Рекомендации и обратная связь

| Method | Path | Auth / роль | Description | User Story |
|---|---|---|---|---|
| POST | `/recommendation-runs` | Без входа | Запуск pipeline для среза, целевого НБС и набора фильтров. | US-005, US-006, SS-002, SS-003 |
| GET | `/recommendation-runs/{run_id}` | Без входа | Сводка запуска, использованный набор правил, статус и число результатов. | US-005, SS-003 |
| GET | `/recommendations?run_id={id}&status={status}` | Без входа | Страница рекомендаций с фильтром по применимости/результату и сортировкой по rank. | US-005, SS-003 |
| GET | `/recommendations/{recommendation_id}` | Без входа | Результат по одному клиенту: применимость, score/rank, объяснение, критерии и ограничения данных. | US-006, SS-002 |
| POST | `/recommendations/{recommendation_id}/feedback` | Без входа; пользователь анализа по сценарию | Сохранить `accepted`, `deferred` или `irrelevant` и обязательную причину. | US-007 |

### `POST /recommendation-runs`

**Request JSON:** `snapshot_id`, `product_id` (должен быть НБС), согласованные фильтры.  
**Предлагаемый синхронный `201` response:** `run_id`, `snapshot_id`, `product_id`, `run_status`, `rule_set_id` (если применён), число кандидатов и сводные статусы. Результаты постранично читаются через `GET /recommendations`.  
**Поведение без правил:** запуск может вернуть результаты со статусом `insufficient_data`; отсутствие критериев не должно приводить к положительной применимости или выдуманному score. Скоринг демонстрационный, качество на синтетике не заявляется.  
**Ошибки:** `404` срез или НБС не найден; `422` тип продукта неверный, фильтр недопустим или срез несовместим с запуском.

### `POST /recommendations/{recommendation_id}/feedback`

**Request JSON:** `{ "status": "accepted|deferred|irrelevant", "reason": "..." }`.  
**Предлагаемый `201` response:** созданная отметка и время.  
**Ошибки:** `404` рекомендация не найдена; `422` неизвестный статус или пустая причина. Идентификатор пользователя не сохраняется: входа в локальном MVP нет, автоматического переобучения на feedback не предусмотрено.

## 6. Продуктовые связки

| Method | Path | Auth / роль | Description | User Story |
|---|---|---|---|---|
| POST | `/product-bundles/analysis` | Без входа | Рассчитать и сохранить наблюдаемые сочетания продуктов по срезу с основанием; не формировать коммерческое предложение без соответствующего источника. | US-008 |
| GET | `/product-bundles?snapshot_id={id}&product_id={id}` | Без входа | Вернуть связки/бандлы, их продукты, тип, источник и условия, если они есть. | US-008, US-010 |

**Request JSON для анализа:** `snapshot_id`, опционально `product_id` и фильтры.  
**Response:** список сохранённых `product_bundles` с элементами, основанием/происхождением и доступной уверенностью. Метрика частоты/значимость связи и поведение повторного запуска (замена или новая версия результата) пока не определены. Условия или скидки указываются только при наличии источника; совместная встречаемость не объявляется готовым коммерческим предложением.

Анализ связок — логическая функция Backend API в C4 v0.6. Открыто, рассчитываются ли они по запросу или подготавливаются при импорте/обновлении среза; `POST /product-bundles/analysis` пока означает явный запуск по запросу.

## 7. Сравнение периодов

| Method | Path | Auth / роль | Description | User Story |
|---|---|---|---|---|
| GET | `/snapshot-comparisons?base_snapshot_id={id}&compare_snapshot_id={id}&product_id={id}` | Без входа | Сравнить два среза и вернуть изменения покрытия/состояний с фильтрами. | US-009 |

Ответ включает обе даты, добавленные/исчезнувшие клиентские профили и связи, а также изменившиеся продуктовые состояния. Параметры времени должны относиться к двум разным существующим срезам; точная гранулярность даты ещё открыта.

## 8. Аналитические отчёты и экспорт

| Method | Path | Auth / роль | Description | User Story |
|---|---|---|---|---|
| GET | `/reports/analysis?run_id={id}` | Без входа | Данные/предпросмотр аналитического отчёта по запуску для отображения в интерфейсе. | US-010 |
| POST | `/exports/reports` | Без входа | Сформировать и вернуть аналитический отчёт PDF или PPTX с выбранными полями и фильтрами. | US-010, US-011 |

**Request JSON для экспорта:** `run_id`, `format` (`pdf` или `pptx`), `fields[]`, актуальные фильтры и выбранный набор периодов, если включено сравнение.  
**Response:** бинарный файл правильного MIME-типа и `Content-Disposition: attachment`; экспортируемый файл не сохраняется на сервере согласно C4.

**Экспорт графа:** отдельного API endpoint нет по гипотезе C4 v0.6 — веб-клиент экспортирует текущее визуальное состояние. Клиентская операция должна поддержать PNG/SVG/PDF/PPTX и выбрать поля/состояние, видимые пользователю. Если решение изменится и граф будет формировать backend, добавить `POST /exports/graph`.

| `product_bundles`, `product_bundle_items` | `POST /product-bundles/analysis`, `GET /product-bundles`. |

## Приложения

### Коды ошибок

| HTTP | Code | Описание |
|---:|---|---|
| 400 | `INVALID_REQUEST` | Некорректный JSON или query parameters. |
| 401 | `UNAUTHORIZED` | Не используется в локальном MVP; зарезервирован для будущего auth-профиля. |
| 403 | `FORBIDDEN` | Не используется в локальном MVP; роль-ограничения и будущая авторизация ещё не реализованы/согласованы. |
| 404 | `NOT_FOUND` | Срез, клиент, продукт, рекомендация или preview не найдены. |
| 409 | `CONFLICT` | Дубли Client ID в одном импорте, повторное подтверждение preview или конфликт каталога. |
| 413 | `PAYLOAD_TOO_LARGE` | Файл превышает лимит; лимит нужно установить. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Формат не поддерживается (например, старый XLS). |
| 422 | `VALIDATION_ERROR` | Поля, идентификаторы, фильтры или бизнес-условия невалидны. |
| 500 | `INTERNAL_ERROR` | Непредвиденная ошибка сервера; не включать содержимое файла/заметок в технический ответ без решения ИБ. |

### Формат ошибки — предложение

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Часть строк не прошла проверку",
    "details": [
      {
        "row": 12,
        "field": "inn",
        "issue": "INVALID_FORMAT"
      }
    ]
  }
}
```

### Пагинация — предложение

`?page=1&limit=50` для каталогов, профилей и списков рекомендаций. Ответ: `{ "items": [], "pagination": { "page": 1, "limit": 50, "total": 0 } }`. Пределы `limit`, объём preview/issues и способ постраничного получения подграфа требуют проверки на целевом моковом наборе.

## Открытые решения перед реализацией

1. Как назначать демонстрационные роли администратора/аналитика без отдельного входа и как API должен различать запись/чтение.
2. Импорт атомарный или частичный; какие ошибки блокируют commit, какие строки оператор может исключить, сколько живёт preview.
3. Редактирование и неизменность срезов: можно ли править профиль/состояние после запуска анализа или исправление должно создавать новый срез.
4. Лимит файла, число выдаваемых nodes/edges, `limit`/timeout и синхронность импорта, расчёта NBO, анализа bundles и экспорта.
5. Критерии применимости ДМС и допустимые поля проверки ИНН/КПП. Положительный результат невозможен без согласованных критериев.
6. Этап расчёта продуктовых связок: по запросу или при импорте; формула частоты/уверенности и источник условий/скидок.
7. Конкретный открытый источник и его структура не выбраны; решить, достаточно ли для подготовленного контекста общего импорта, или нужен отдельный маршрут. API для live внешних систем не включён.
8. Graph export остаётся клиентским по C4-гипотезе; проверить реализацию форматов PNG/SVG/PDF/PPTX после выбора библиотеки.
