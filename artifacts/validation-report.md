# Validation Report: ПСБ × ИТМО — анализ наполненности НБС

> **Дата:** 2026-11-18  
> **Артефакты:** `brief.md`, `usm.md`, `nfr.md`, `c4-architecture.md` v0.6, `er-diagram.md` v0.3, `api-inventory.md` v0.1; справочник `schema.xlsx`  
> **Статус:** **NEEDS WORK ⚠️**

## Executive Summary

Основной сценарий отражён в предложенном API Inventory: 24 endpoint-операции покрывают импорт, просмотр наполненности, рекомендации, связки, сравнение и обязательный экспорт. Маршруты согласованы с USM и текущими ER/C4; инвентарь остаётся обзором для планирования, а не утверждённой OpenAPI-спецификацией.

До реализации остаются решения о демонстрации прав администратора и аналитика, обработке частичных ошибок импорта, сроке жизни preview и лимитах синхронных операций. Они не создают противоречий между артефактами, но влияют на API-контракт и поведение интерфейса.

## Verdict

### ⚠️ NEEDS WORK — требуется доработка

Критических противоречий не найдено. Основные истории имеют API-покрытие, авторизация корректно не включена для локального демо без отдельного входа, а группировка продуктовых связок добавлена в описание Backend API. До реализации нужно закрыть или явно ограничить открытые решения, перечисленные в Action Items.

1. [ ] **Роли MVP** — решить, как показать разделение администратора и пользователя анализа при отсутствии отдельного входа; затем синхронизировать USM, C4 и API.

3. [ ] **Производительность** — после генерации мокового набора зафиксировать объёмы и проверить синхронный импорт, расчёт NBO, связок и экспорт; при необходимости добавить асинхронные операции и Sequence.
4. [ ] **Открытые источники** — выбрать источник и формат подготовки контекста; текущий API не предполагает live-интеграцию.
5. [ ] **Продуктовые связки и рекомендации** — запросить критерии ДМС; определить метод/частоту связок. До получения критериев положительную применимость не показывать.
